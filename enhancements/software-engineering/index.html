Project context

From an academic AI prototype to a modular software application

The Pirate Intelligent Agent originated in CS 370: Current/Emerging Trends in Computer Science. The original project used Python and TensorFlow/Keras to train a deep Q-learning agent to navigate an 8-by-8 maze and locate treasure. My primary contribution focused on implementing the reinforcement-learning training process within a Jupyter Notebook supported by existing maze and experience management classes.

For my first CS 499 enhancement, I redesigned the application around software engineering principles rather than changing the underlying learning algorithm. I separated configuration, maze behavior, replay memory, neural-network responsibilities, and training coordination into independent Python components. A standalone main.py entry point replaced the notebook-dependent execution workflow.

The objective was to preserve the original navigation problem while improving maintainability, reliability, testability, and extensibility. This architecture also established the foundation for the subsequent Algorithms and Database enhancements.

Engineering decisions

Modular architecture, stronger validation, and reliable execution

Separation of concerns

Refactored the notebook-based implementation into independent Python components for configuration, maze behavior, replay memory, neural-network operations, and training coordination.

A standalone main.py entry point allows the application to execute without relying on a sequence of Jupyter Notebook cells.

Configuration and state management

Introduced a validated configuration dataclass, an Action enumeration, and bounded replay memory to make application behavior more predictable.

Corrected an invalid-action state defect in the original maze logic and restricted agent action selection to currently valid movements.

Neural-network architecture

Encapsulated model creation, prediction, action selection, and target-network synchronization within the learning agent. Updated model construction to use an explicit keras.Input layer.

Automated testing and reliability

Developed ten unit tests covering configuration, environment behavior, invalid actions, replay memory, and neural-network validation. All ten tests passed.

Added type hints, documentation, input validation, controlled exceptions, and reproducible random seeds to improve maintainability and reliability.

Validation

Testing the architecture, not just the algorithm

The enhanced application was validated through ten automated unit tests using Python's unittest framework. These tests covered configuration validation, environment initialization, movement handling, invalid actions, maze values, bounded replay memory, and neural-network state and prediction behavior.

A particularly important test verified that an invalid maze movement correctly updates the environment's state. This addresses a defect identified during the original code review and demonstrates how automated testing can protect behavior during architectural refactoring.

Integration validation included a standalone 15-epoch training run using the original CS 370 maze. The application recorded reward, loss, and epsilon histories while demonstrating that the independently organized components function together.

Enhancement narrative / reflection

Why this artifact matters

I selected the Pirate Intelligent Agent because it represents an important stage in my development in artificial intelligence. Revisiting the project allowed me to examine how my approach to software engineering has evolved from implementing an algorithm to designing a complete, maintainable application.

The most significant challenge involved separating components that had originally been closely connected within the notebook. I had to establish clear responsibilities for configuration, environment behavior, replay memory, neural-network operations, and training coordination while preserving the original navigation requirements.

During validation, I discovered that the maze initially used by the standalone application differed from the original CS 370 environment. I corrected the maze configuration and reran the application to ensure that architectural improvements did not unintentionally change the original problem.

This enhancement reinforced an important engineering principle: a functioning algorithm is only one part of a reliable software system. Maintainability, testability, validation, and clear component boundaries determine whether that system can be understood, verified, and extended.
