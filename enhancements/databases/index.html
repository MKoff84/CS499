Project context

From intelligent navigation to persistent experiment data

The Pirate Intelligent Agent originated in CS 370 as a Python-based deep Q-learning application designed to navigate an 8-by-8 maze. The first CS 499 enhancement reorganized the application into modular components, while the second introduced A* and breadth-first search for deterministic pathfinding comparisons.

For Enhancement Three, I extended the application with a SQLite relational database that preserves experiment results beyond an individual program execution. Rather than relying exclusively on temporary output, the application can store training runs and algorithm results for later retrieval and comparison.

The database uses two related tables: experiment_runs and algorithm_results. Primary and foreign keys establish relationships, while constraints, parameterized SQL statements, and transaction management support data integrity and reliable database operations.

Engineering decisions

Relational architecture, data integrity, and secure operations

Relational database design

Designed a SQLite database using two related tables: experiment_runs and algorithm_results. Primary and foreign keys connect experiment records with their associated algorithm results, reducing unnecessary duplication and supporting structured queries.

Data integrity and security

Implemented database constraints, foreign-key relationships, and parameterized SQL statements. These measures help prevent invalid records, protect query execution from SQL injection, and maintain consistency between related data.

Persistent experiment storage

Extended the application to save deep Q-learning experiment information and A*/BFS algorithm results. Stored records can be retrieved after execution, supporting repeatable comparisons and future analysis.

Transaction and connection management

Used managed SQLite connections and transactions to support reliable database operations. Added indexes to improve access to relevant records and automated tests to verify persistence, relationships, and expected database behavior.

Validation included database-specific tests alongside the existing software engineering and algorithm tests. All 26 automated tests passed, providing evidence that the database integration preserved existing functionality.

Validation

Verifying persistence, integrity, and reliability

The completed database enhancement was validated using Python's unittest framework. The final application passed 26 automated tests, including six database-specific tests. These tests complemented the existing software engineering and pathfinding tests.

Database validation focused on creating and retrieving experiment records, preserving relationships between experiment runs and algorithm results, and confirming that stored information remained available after database connections were closed and reopened.

Parameterized SQL statements were used to separate user-supplied values from SQL commands. Foreign-key constraints and managed transactions provided additional safeguards for maintaining consistent records.

During testing, I also addressed a temporary SQLite connection-management issue on Windows. Correcting connection cleanup allowed the tests to complete without leaving temporary database files locked.

Enhancement narrative / reflection

Turning experiment results into reusable knowledge

I selected the Pirate Intelligent Agent for my third enhancement because it provided an opportunity to connect artificial intelligence development with practical database engineering. The original application demonstrated reinforcement learning, but it did not provide a structured relational system for preserving and comparing experimental results.

By implementing SQLite persistence, I expanded the project beyond individual training sessions. Experiment records and algorithm results can now be stored, retrieved, and analyzed without depending exclusively on temporary console output or in-memory data.

The enhancement strengthened my understanding of relational schema design, primary and foreign keys, SQL parameterization, transactions, indexing, and automated database testing. These capabilities are especially relevant to research applications where experimental results must remain accessible and traceable over time.

One challenge involved managing SQLite connections during automated testing on Windows. Resolving the connection cleanup issue reinforced the importance of resource management and testing under realistic execution conditions.

This enhancement demonstrates my progress toward the computer science program outcomes involving computing solutions, technical tools, secure data management, and professional engineering practices. Together, the three enhancements illustrate how software architecture, algorithms, and databases contribute to a more complete computing system.
