Project context

From learning-based navigation to algorithmic comparison

The Pirate Intelligent Agent originated in CS 370: Current/Emerging Trends in Computer Science. My original work centered on implementing the deep Q-learning training process within a notebook using supporting course-provided classes. In CS 499, I first refactored the project into a modular application. For this second enhancement, I implemented A* search and breadth-first search (BFS) as deterministic alternatives for solving maze navigation.

Using the same navigation problem makes the trade-offs visible: the reinforcement-learning agent learns through repeated experience, while A* and BFS systematically explore a known maze to find a shortest path.

Engineering decisions

Two search strategies, deliberate data structures

A* search

A* evaluates candidate positions using f(n) = g(n) + h(n), where g is accumulated path cost and h is the Manhattan-distance estimate to the goal. Four-direction movement and unit costs make this heuristic appropriate for the maze.

  • Min-heap: prioritize frontier states
  • Dictionaries: predecessor and cost tracking
  • Set: explored-state membership
  • Tuples and list: coordinates and final path

Breadth-first search

BFS explores reachable positions in increasing distance from the start. Because each move has unit cost, BFS also finds a shortest path without using a goal-directed heuristic.

  • Deque: FIFO search frontier
  • Dictionary: visited/predecessor tracking
  • Tuples: immutable positions
  • List: reconstructed shortest path

Validation

Tested and maintainable

Milestone Three included 20 passing automated tests covering the modular application and pathfinding behavior. These checks included valid shortest paths, equal-cost comparisons, blocked starts and goals, out-of-bounds coordinates, and unreachable destinations. Following the later database enhancement, the integrated application passed 26 tests in total.

The search implementations reside in dedicated modules, keeping algorithm logic separate from the maze environment, learning agent, and training workflow.

Enhancement narrative / reflection

Why this artifact matters

I chose to extend the Pirate Intelligent Agent because it provided a direct way to compare different computational approaches to the same problem. A* required me to think carefully about heuristic quality, priority ordering, path costs, and state tracking. BFS provided a straightforward baseline that helped me check whether the heuristic-guided implementation was returning an optimal solution.

One lesson was that selecting an algorithm involves more than observing a single runtime measurement. The maze structure, search order, frontier data structure, and cost assumptions all affect what a comparison means. Testing both algorithms against controlled cases strengthened my ability to validate an implementation instead of assuming that a successful-looking path was correct.

This enhancement supports the CS 499 outcomes involving algorithmic solution design, evaluation of trade-offs, well-founded computing techniques, and professional technical communication. It also connects to my longer-term interests in AI, autonomous navigation, aerospace simulation, and scientific computing, where selecting and validating algorithms is essential.

Instructor feedback on Milestone Three confirmed that the submission met the key requirements and identified no major areas requiring improvement. This presentation is a polished web summary; the complete milestone narrative and source artifacts should also be included in the final repository.
