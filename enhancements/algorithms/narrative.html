Artifact Description

The artifact I selected for my Algorithms and Data Structures enhancement is the Pirate Intelligent Agent that I originally developed in CS 370: Current/Emerging Trends in Computer Science. The original project used deep Q-learning to train an intelligent agent to navigate a maze and locate a treasure. I selected the same artifact for this enhancement because maze navigation provides an opportunity to examine the same computational problem using different approaches. During my Software Design and Engineering enhancement, I had already refactored the original notebook-centered project into a modular application with separate components for the environment, intelligent agent, replay memory, configuration, training, and automated testing. For Milestone Three, I extended that architecture by implementing A* pathfinding and breadth-first search (BFS), allowing the project to demonstrate traditional search algorithms and data structures alongside the existing reinforcement-learning approach.

Justification for Inclusion and Enhancement

I included this artifact in my ePortfolio because the enhancement demonstrates that solving a problem in computer science involves more than implementing an algorithm that works. It also requires selecting appropriate algorithms and data structures and understanding the trade-offs involved in those choices. The primary enhancement was an A* pathfinding algorithm that uses Manhattan distance as a heuristic to guide the search toward the treasure. The implementation uses a min-heap priority queue to manage the search frontier, a set to track explored positions, dictionaries to maintain path costs and predecessor relationships, tuples to represent maze coordinates, and a list to reconstruct the completed path. I also implemented BFS as an uninformed-search baseline using a FIFO queue. This allowed me to compare two algorithms that can both find a shortest path in the unit-cost maze but approach the search problem differently.

The comparison helped demonstrate the effect of algorithm selection rather than simply assuming that one method was better. In the comparison maze, A* and BFS both found an optimal path with a length and total cost of 14. A* explored 25 nodes compared with 26 for BFS. Although the difference was small for this particular maze, it demonstrated how the heuristic can influence the order in which states are explored while still preserving an optimal solution. I also added validation for blocked and out-of-bounds positions, handling for unreachable goals, path reconstruction, and automated tests for both search algorithms. The final project passed all 20 automated tests, including the existing tests from the Software Design and Engineering enhancement. This confirmed that the new algorithmic functionality worked without breaking the existing application.

Course Outcomes

This enhancement most directly addressed the third Computer Science program outcome: designing and evaluating computing solutions using algorithmic principles and computer science practices while managing trade-offs in design choices. Instead of implementing A* in isolation, I compared it with BFS and considered how their different data structures influence the search process. BFS uses a FIFO queue to explore states according to their distance from the starting point, while A* uses a priority queue and heuristic to determine which state should be considered next. This required me to think about why a particular data structure was appropriate for an algorithm rather than choosing one simply because it was familiar.

The enhancement also continued my progress toward the second and fourth course outcomes. The updated documentation and comparison results communicate the technical design in a way that can be understood by someone reviewing the ePortfolio, while the modular implementation demonstrates the use of established tools and computing techniques to extend an existing software system. I do not need to change my overall outcome-coverage plan at this point. Course Outcome 3 is now represented much more directly through this enhancement, while the upcoming Database enhancement will provide additional evidence for Outcome 4. Security-minded validation and defensive programming from the previous enhancement also remain part of the artifact and continue to support Outcome 5.

Reflection on the Enhancement Process

One of the most important things I learned from this enhancement was the difference between a learning-based solution and a deterministic search algorithm. The existing deep Q-learning agent learns action values through repeated interaction with the environment, whereas A* uses known information about the maze and a heuristic to deliberately search for a path. Implementing BFS as a baseline made this difference even clearer because BFS can also find an optimal path without using a heuristic. Comparing the approaches reinforced that the appropriate algorithm depends on what information is available, the structure of the problem, and the performance characteristics that matter to the application.

The main challenge was making sure that the new algorithms handled more than the successful case. Finding a path through a simple maze was only part of the enhancement. I also needed to consider blocked positions, invalid coordinates, unreachable goals, path reconstruction, and whether the algorithms returned consistent costs. Building automated tests around those conditions helped me view algorithm design as part of a larger software system rather than as an isolated coding exercise. By the end of the enhancement, the project had progressed from demonstrating only reinforcement learning to showing multiple approaches to maze navigation and the reasoning behind their data structures and design choices. This makes the artifact a stronger representation of my ability to evaluate computing solutions rather than simply implement them.
